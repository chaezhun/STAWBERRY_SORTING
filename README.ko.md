# 딸기 자동 분류 시스템

컨베이어 위를 지나는 딸기를 카메라와 NPU가 신선·덜익음·썩음으로 판별하고, 벨트 끝의
회전판이 종류별로 배출합니다. 칩도 운영체제도 언어도 다른 임베디드 보드 3개를 하나의
라인으로 묶었습니다.

중앙대학교 고급프로젝트, 텔레칩스 팹리스 실무교육과정 연계. 2인 팀, 2026년 3월–6월.

## 핵심 결과

| | |
|---|---|
| 보드 | 3대 — 8 TOPS NPU(Yocto), 듀얼코어 제어(Linux + FreeRTOS), MCU 구동 |
| 통신 | 이더넷 TCP → IPC 공유메모리 → CAN 버스 |
| 신뢰성 | 초당 2프레임·잦은 오검출 조건에서 **딸기 1개당 정확히 1회 동작** |
| 운영 | SSH 한 줄로 전체 라인 기동·종료. UART 케이블 없음 |
| 담당 | 제어·구동 보드, 통신 체인, 시스템 통합 |

## 통신 체인

```
 카메라 --> [ AI-G ]  --이더넷 TCP-->  [ D3-G A72 ]
            NPU 위의                    분류 판단, 동작 시점 결정
            YOLOv8n                             |
                                                | IPC 공유메모리
                                                v
                                       [ D3-G R5, FreeRTOS ]
                                                |
                                                | CAN 버스
                                                v
                                       [ VCP-G ]  서보·LED·LCD
```

| 보드 | 역할 | 구성 |
|---|---|---|
| AI-G | 인식 | 카메라 + NPU(8 TOPS), Yocto Linux, YOLOv8n |
| D3-G | 제어 | A72(Linux)가 판단하고, R5(FreeRTOS)가 공유메모리를 CAN으로 중계 |
| VCP-G | 구동 | TCC70xx MCU, 서보·LED 3색·LCD |

구간마다 통신 방식이 달라서 이걸 맞물리는 게 작업의 대부분이었습니다. AI-G는 최소
Yocto 이미지라 Python이 아예 없어서, 결과 전송을 `sh` + `awk` + `nc`로 짰습니다. D3-G
두 코어 사이는 `/dev/tcc_ipc_micom`, 거기서 구동 보드까지는 CAN이고, 서보는 각도 1바이트,
LED는 2바이트, LCD 카운터는 4바이트로 포맷을 정했습니다.

## 딸기 1개당 정확히 1회

카메라가 초당 2프레임이고 모델 오검출도 무시할 수준이 아닙니다. 감지하자마자 동작하면
딸기 하나에 회전판이 여러 번 돌거나, 한 프레임 튄 좌표에 헛돕니다. 감지와 서보 사이에
다섯 단계를 뒀습니다.

| 단계 | 규칙 |
|---|---|
| 신뢰도 | 50% 미만은 무시 |
| 트리거 박스 | X·Y가 모두 회전판 자리 범위 안에 들어와야 함 |
| 디바운스 | 박스 안에서 연속 3프레임 |
| 재무장 gap | 그 종류가 1.5초 이상 안 보였다가 다시 보여야 새 딸기 |
| 비차단 서보 | 동작 중에 들어온 트리거는 큐에 쌓지 않고 버림 |

마지막 항목은 실패에서 나왔습니다. 회전판이 하나라 서보 호출을 잠금으로 직렬화했더니,
과다 트리거가 1.3초짜리 동작으로 쌓여서 딸기가 이미 지나간 빈 벨트 위에서 계속 돌았습니다.
잠금을 비차단으로 바꿔 백로그를 빼내는 대신 아예 없앴습니다.

## 오검출 세 가지

검증 mAP50이 0.99인 모델도 실제 벨트 위에서는 다르게 굽니다. 원인이 달라서 해결도
따로 했습니다.

| 문제 | 원인 | 해결 |
|---|---|---|
| 너무 빠르고 예민한 감지 | 세로(Y) 좌표만으로 판단 | X·Y를 모두 쓰는 2D 박스 — 회전판 직전 자리에서만 인정 |
| 덜익음 과검출 | 학습량이 가장 많아 매 프레임 검출되고, 박스에 들어오자마자 트리거 | 덜익음 전용 축소 박스, 진입변을 안쪽으로 |
| 신선 오분류 | 신선이 가끔 썩음·덜익음으로 검출 | 신선이 1프레임이라도 잡히면 2초간 다른 분류 차단 |

마지막 해결은 오분류의 **방향**을 관찰한 데서 나왔습니다. 신선이 불량으로 잘못 잡히는
건 잦지만, 불량이 신선으로 잡히는 건 드뭅니다. 그래서 신선 신호가 신뢰할 수 있는
쪽이고, 로직을 일부러 비대칭으로 뒀습니다. 신선은 1프레임에 발동하고 썩음·덜익음은
3프레임을 요구하므로, 경합에서 신선이 항상 이깁니다.

## 케이블 없는 운영

원래는 보드마다 UART를 꽂고 각각 명령을 넣어야 했습니다. 지금은 제어 코드가 SSH로
AI-G 인식을 시작시키고, 30초 무감지면 전부 정리하고 종료합니다. 명령 하나로 끝납니다.

가는 길에 AI-G IP를 systemd 서비스로 재부팅에도 유지되게 하고, 보드 간 무비번 SSH 키를
설정하고, NetworkManager가 static IP를 지우는 걸 `nmcli managed no`로 막았습니다. R5에
수동 `log on`이 필요하다는 전제도 콜드 파워사이클로 재검증했더니 필요 없었고, 마지막
UART 케이블이 그렇게 없어졌습니다. 콜드부팅부터 WiFi만으로 동작합니다.

## 재플래싱 없는 튜닝

구동 보드 펌웨어를 다시 올리려면 WSL 빌드 → 부트 모드 → FWDN → 재부팅을 매번 거쳐야
합니다. 그래서 현장에서 조정하는 값은 전부 Python 제어부에 둡니다. 회전 각도 3개,
유지 시간, 트리거 박스 좌표, 디바운스 프레임 수, 재무장 gap. 바꾸려면 파일 하나 복사하고
다시 실행하면 됩니다. 카메라 위치가 바뀌어 박스를 다시 실측한 게 한 번이 아니라서,
이 구조가 실제로 값을 했습니다.

## 하드웨어에서 겪은 것

회전판은 처음에 MG90S로 시작했는데, 이게 360도 연속회전형이라 속도만 제어되고 위치는
안 됩니다. 시간으로 각도를 맞추려니 매번 밀려서, 위치제어형 SG90으로 바꾸고 CAN으로
목표 각도를 직접 보내는 방식으로 전환했습니다.

LCD는 백라이트만 켜지고 글자가 안 나왔고 I2C 스캔이 전 주소에서 0x00이었습니다. 두 포트에
스캐너를 붙여도 안 잡혔는데, 원인은 배선이었습니다. 이 보드에서 I2C 라우팅이 불가능한
핀에 물려 있었습니다. 정식 헤더로 옮기고 펌웨어 포트를 맞춰 해결했습니다.

무선 운영 중에 LED와 CAN 로그는 정상인데 모터만 안 도는 일이 있었습니다. 그 덕에 CAN·R5·VCP
경로는 멀쩡하다고 격리했고, 남은 건 서보 배선이었습니다. 점퍼 접합부에 낀 절연테이프
때문이었습니다.

## 3D 출력물

세 부품 모두 CadQuery로 치수를 전부 상수화해 모델링했고 Bambu X1-Carbon으로
출력했습니다. STEP·STL 출력물과 부품별 렌더를 함께 뒀습니다.

- **하우징** 96.5 × 123.5 × 107.0 mm, 보드 3개를 3층 선반에 수납. 전원·포트·카메라 구멍 포함
- **회전판** 110 × 50 × 1.3 mm, 좌우 벽 있음. SG90 스플라인에 직접 압입
- **지지대** 서보를 지면과 30도로 받쳐 신선 딸기가 굴러 통과하게 함. 서보 포켓과 배선 통로 포함

지지대를 처음에 속 빈 쉘로 만들었더니 비수밀 형상이 되어 슬라이서가 거부했습니다.
수밀 솔리드로 두고 인필로 비우는 방식으로 바꿨습니다.

## 빌드와 실행

**사전 조건** — VCP-G 펌웨어 빌드용 텔레칩스 TOPST SDK(WSL에서 빌드), D3-G의 Python 3,
AI-G에 배포된 학습 완료 모델.

1. **구동 보드** — `BOARD_CODE/vcp-g/`를 SDK로 빌드해 FWDN으로 플래싱합니다. 핀맵이나
   CAN 포맷이 바뀔 때만 다시 하면 됩니다. 튜닝 파라미터는 전부 제어부에 있습니다.
2. **인식 보드** — 모델 파일 3개를 `/usr/share/strawberry_shifted_v2_quantized/`에 두고
   `ai_result_sender.sh`를 `/home/root/`로 복사합니다. 모델 변환·배포 과정은
   [`NPU_PIPELINE.md`](BOARD_CODE/ai-g/NPU_PIPELINE.md)에 있습니다.
3. **제어 보드** — D3-G에서 `sudo python3 fruit_controller.py`를 실행합니다.
   `ORCHESTRATE = True`면 자기 IP를 고정하고, SSH로 AI-G 인식을 시작시킨 뒤,
   30초 무감지 시 전부 정리하고 종료합니다.

사전 1회 설정: AI-G의 고정 IP와, 제어 보드에서 AI-G로 가는 무비번 SSH 키.
